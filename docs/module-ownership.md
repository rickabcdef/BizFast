## 协作约定

- 每人基于 `pm` 拉自己的分支（`sde-A` / `sde-B` / `sde-C` / `sde-D`），做完先推自己的分支，再合并回 `pm`。
- 改接口 → 同步更新 `docs/api-contract.md` 与 `frontend/src/types/index.ts`。
- 公共能力（鉴权、错误码、平台适配）优先沉淀到 `core/` 与 `utils/`，避免重复实现。
- **一个模块只允许一套实现**：账号体系以 `services/auth_service.py` + `routers/auth.py` 为唯一出口，
  不要再另起一套并行的 `services/auth.py`；埋点统一走 `/api/events/track` + `services/funnel.py`。
- P0 模块是网页版上线门槛，优先于 P1；V1.1–V1.3 的模块在现金流转正前一律不动。

## V5.0 关键口径（避免各端数字打架）

| 口径 | 定义 | 来源 |
|---|---|---|
| 已下载 | 用户**真实**下载过至少一件交付物（`dl=1` 或 ZIP） | `Order.downloaded_at` |
| 退款路径 | 未下载 = `self`（自助即时退）；已下载 = `review`（人工审核） | `Order.refund_review` |
| 已购次数 | 状态属于 paid / generating / delivered / refunded 的订单数 | `Order` |
| 已用启动包数 | 实际生成过的 `Package` 数 | `Package` |
| 额度剩余 | 单次礼包 = 已购 − 已用；月/年卡 = 不限次 | `membership_quota()` |
| 今日限制 | 该商机**当日真实支付成功**的订单数 vs `opportunity_daily_limit`（默认 50） | `Order` |
| 手机号展示 | 后台一律脱敏为 `138****5678` | `_mask_phone()` |
| 来源渠道 | `邀请注册` > 埋点渠道（`FunnelEvent.source`）> `自然流量`；后台按此标签筛选 | `resolve_user_source_index()` |
| 邀请绑定 | 分享链接 `?inviter=CODE` → 落地即暂存 → 登录（手机号/微信**同一条路径**）自动绑定；**首次绑定后不可修改** | `share_service.bind_invite()` + `frontend/src/services/api.ts` |
| 支付兜底 | 回调 + 主动查单双保险；渠道已扣款而本地待支付 → **自动补单**，查不到则告警交人工 | `payment_service.query_order()` |
| 城市口径 | 前后端同一套城市库；中文标准名，不带「市」后缀入库 | `app/data/cities.py` ↔ `constants/cities.ts` |
